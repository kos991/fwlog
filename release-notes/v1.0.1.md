# fwlog v1.0.1

v1.0.1 是 v1.0.0 的补丁版本，修复导入、查询和自动扫描中的逻辑错误，并提升日志导入速度。接口契约和数据格式不变，可直接用升级包从 v1.0.0 升级。

## 修复的问题

- **深信服日志源端口始终为 0。** 解析器里“源端口”标签是乱码，所有深信服日志的 `src_port` 都没有被解析。升级后新入库的数据会带上正确的源端口；已入库日期需要重建才能补齐。
- **多日志源查询可见性互相覆盖。** 同一天有多个日志源时，只按其中一个来源的入库状态决定整天是否可查，可能漏查已就绪的来源，或查到未入库完成的来源。现在每个来源单独判断，查询条件带上来源。
- **查询第 2 页以后无法翻页。** 偏移分页时 `has_more` 始终为 false，查询插件等客户端在第 2 页就停止翻页。
- **自动扫描失败仍被记为完成。** 定时扫描中任一来源导入失败时，仍会写入本次扫描时间，失败时段不会再重试。现在只有全部来源成功才记录。
- **重建时删除分区失败不更新状态。** 部分数据可能已被删除，但入库状态仍是“已就绪”，之后的同步会跳过该日期。现在会标记为失败。
- **允许两个日志源使用相同的存储 ID。** 这会让导入、分区删除和入库状态互相覆盖。保存配置时现在会拒绝。
- **查询日期边界在夏令时日计算错误。** 改为按日历日计算一天的结束时间。

## 性能改进

- 单行日志解析快 2–4 倍，解析过程不再逐行分配内存。

  | 格式 | v1.0.0 | v1.0.1 |
  | --- | --- | --- |
  | 深信服 | 1444 ns | 617 ns |
  | 华为 USG | ~2.4 µs | 578 ns |
  | H3C | ~2.2 µs | 561 ns |
  | FortiGate | ~2.6 µs | 986 ns |

- 批量写入 ClickHouse 时每行耗时从 505 ns 降到 371 ns，每批内存分配从约 10 万次降到 419 次。
- `WORKERS` 现在真正控制导入并发：同一日志源内会按 `WORKERS` 并行导入多个日期，写入并发也随之调整。v1.0.0 中单日志源时该参数不起作用。默认仍为 `WORKERS=1`，行为与之前一致；调大后导入更快，CPU、内存和 ClickHouse 压力也会相应上升。

## 升级说明

- 使用 `fwlog-upgrade` 升级包升级，ClickHouse 数据与应用配置保留。
- 如需调大导入并发，修改 `/etc/systemd/system/fwlog.service` 中的 `Environment="WORKERS=1"`，然后执行 `systemctl daemon-reload && systemctl restart fwlog`。
- 已入库日期的源端口仍为 0，如需按源端口查询历史数据，请在数据处理页面对相应日期执行重建。
