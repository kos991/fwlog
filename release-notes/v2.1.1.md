# fwlog v2.1.1 补丁版

本版本修复大数据量环境中数据概览导致 CPU 持续过高、历史日期重建不完整，以及自动扫描和失败日期重建不稳定的问题。

## 本次更新

- 数据概览改用 ClickHouse 按日预聚合表，不再为每次页面请求扫描 30 天原始日志。
- 概览与排行拆分加载；排行增加 5 分钟缓存、同键并发请求合并和过期结果降级。
- ClickHouse 冷排行和 GeoIP 聚合限制为单 worker，避免冷刷新占满多核 CPU。
- 日期重建会同步清理原始日志、总量聚合和 IP 聚合分区，重复重建不会产生聚合数据叠加。
- 修复失败日期不能重新导入、手动指定日期范围处理不完整的问题。
- 自动扫描跳过当天未归档日志，按来源串行执行，并避免同一来源任务重复并发。
- 默认入库 worker 调整为 1，应用进程使用普通调度优先级，降低入库对查询和系统服务的影响。
- RPM/DEB 升级包会自动在线回填历史概览数据，完成对账后再短暂停止旧应用并切换聚合表。

## 性能验证

在 1.805 亿行测试数据上连续请求 10 分钟：

- 系统 CPU 平均 `3.38%`，峰值 `20.53%`，600 个秒级样本均未超过 `30%`。
- 概览接口 P95 为 `93.47ms`。
- 缓存排行接口 P95 为 `4.62ms`。
- 冷排行约 `7.4–8.1s`，使用单线程控制 CPU 峰值。
- 原始表、总量聚合、源 IP、目标 IP 和目标子网均为 `180,553,233` 行；30 天 Top 10 对账一致。

## 升级说明

- 支持从 `v2.1.0` 直接升级。
- 升级会创建临时 staging 聚合表并回填历史数据；回填期间旧应用继续提供服务，最终切换时会短暂停服。
- 回填耗时取决于现有日志规模和磁盘性能，ClickHouse 查询固定使用单线程。
- 升级前应确认数据盘有足够空间保存临时聚合表，并保留现有应用和 ClickHouse 数据备份。
- 使用外部 ClickHouse 时，升级主机必须安装可连接目标数据库的 `clickhouse` 或 `clickhouse-client`。
