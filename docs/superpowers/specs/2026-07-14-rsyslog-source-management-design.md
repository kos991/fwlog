# RSyslog 日志源管理与自动归档设计

## 背景

当前日志源页面直接展开所有表单字段，日志源较多时很难扫描，新增、编辑和删除也缺少明确的操作边界。RSyslog 接收器虽然支持 UDP/TCP，但会丢弃远端 IP，同一端口也不能按客户端 IP 路由到不同设备。接收文件只按天写为 `YYYY-MM-DD.log`，没有压缩、移动和保留期清理。

导入器只识别 `*.log-YYYYMMDD` 和 `*.log-YYYYMMDD.gz`，因此归档产物必须遵守该文件名协议，否则接收的日志无法进入现有扫描与入库链路。

## 目标

- 日志源页面使用紧凑列表，新增和编辑统一使用弹窗。
- 日志源的启停、编辑和删除都是明确、可确认、可立即应用的操作。
- RSyslog 日志源可配置客户端 IP 或 CIDR，并按真实远端 IP 匹配设备。
- 多个日志源可共享同一个协议和监听端口，由客户端 IP/CIDR 决定落盘目录和设备 ID。
- 前一天的接收文件自动压缩；归档目录为空时原地压缩，配置后移动到指定目录。
- 归档默认保留 90 天，只有已成功入库的日期才能按保留期删除。

## 非目标

- 不改变文件目录源的导入协议。
- 不在本次改造中引入外部消息队列或独立 Syslog 服务。
- 不把客户端 IP 写入每条 NAT 日志记录；客户端 IP 用于接收路由和运行状态，设备归属仍由 `source_id` 持久化。

## 日志源数据模型

`model.LogSource` 和设置 JSON 增加：

```json
{
  "client_ip": "192.168.10.20",
  "archive_dir": "",
  "archive_retention_days": 90
}
```

- `client_ip`：RSyslog 客户端 IPv4/IPv6 或 CIDR。新增和编辑 RSyslog 源时必填。
- `archive_dir`：可选绝对路径。空值表示压缩后仍保存在 `spool_dir`。
- `archive_retention_days`：归档保留天数，默认 90，界面限制为 1–3650。

RSyslog 源的 `log_dir` 由服务端归一化：`archive_dir` 非空时使用 `archive_dir`，否则使用 `spool_dir`。这保证自动扫描始终查找真实归档产物。

现有旧 RSyslog 源的 `client_ip` 可为空，作为兼容性全匹配路由；在界面中编辑后必须填写。同一监听端点最多允许一条全匹配路由。

## 配置校验与原子应用

服务端在写入设置前完成归一化和校验：

- `source_id` 唯一，且只允许字母、数字、点、下划线和连字符。
- RSyslog 协议只允许 `udp` 或 `tcp`，端口范围为 1–65535。
- `client_ip` 必须是合法 IP 或 CIDR。
- `spool_dir` 和非空 `archive_dir` 必须是绝对路径。
- 同一监听端点不允许重复的 IP/CIDR 匹配规则。
- 同一监听端点存在包含关系的 CIDR 时，使用最长前缀匹配，精确 IP 优先。

校验失败返回 HTTP 400，不修改内存设置、ClickHouse 设置或当前监听器。校验通过后才保存整个日志源列表并重建接收路由。

## 共享端点与客户端 IP 路由

`receiver.Manager` 从“每个日志源一个监听器”改为“每个端点一个监听器”。端点键由以下字段组成：

```text
listen_protocol + listen_host + listen_port
```

每个端点保持一组不可变路由表。UDP 使用 `ReadFrom` 返回的来源地址，TCP 使用连接的 `RemoteAddr`。路由器去除客户端端口后按下列顺序匹配：

1. 精确 IP。
2. 最长前缀 CIDR。
3. 兼容性全匹配路由。

匹配成功后写入该日志源的 `spool_dir`。未匹配客户端不写入任何设备目录，只增加端点拒绝计数并记录限频警告。

路由状态增加：

- `client_ip`：配置的 IP/CIDR。
- `last_client_ip`：最后一次成功匹配的真实远端 IP。
- `last_received_at`：最后接收时间。
- `received_messages`：进程启动后成功接收数。
- `archive_error` 和 `last_archive_at`：最近归档状态。

## 文件写入与自动归档

活跃日志仍写入：

```text
<spool_dir>/YYYY-MM-DD.log
```

归档调度器在服务启动后立即扫描一次，之后每分钟扫描。只处理日期早于当天的 `YYYY-MM-DD.log`，不触碰当天活跃文件。

归档名称为：

```text
<source_id>_<event-date>.log-<archive-date>.gz
```

例如：

```text
rsyslog-main_2026-07-14.log-20260715.gz
```

其中 `event-date` 是日志接收日期，`archive-date` 是压缩日期。该名称能被当前 `ExtractLogDate` 正确解析为事件日期。

- `archive_dir` 为空时，归档产物写在 `spool_dir`。
- `archive_dir` 非空时，归档产物直接写入该目录，不创建年/月子目录，以保持现有扫描器的非递归行为。
- 压缩先写入目标目录中的临时文件，完成并关闭后再原子重命名。
- 归档目录与落盘目录位于不同文件系统时，先在目标目录完成拷贝和重命名，再删除源文件。
- 压缩成功后才删除原始 `.log`；任何错误都保留原文件并写入运行状态。
- 目标归档已存在时验证 gzip 可读后跳过，使重启补扫具有幂等性。

## 保留期清理

清理器只考虑符合 RSyslog 归档命名协议的 `.gz` 文件。当文件的事件日期早于当天减去 `archive_retention_days` 时，还必须满足：

- `ingest_dates` 中存在相同 `source_id + log_date`。
- 日期状态为 `ready`。

状态为 `pending`、`scanning`、`importing`、`failed` 或不存在状态时都不删除。清理错误不影响接收器，但必须进入日志源运行状态和服务日志。

## 前端交互

日志源页从展开表单改为列表。桌面端列为：

```text
设备 ID | 日志名称 | 类型 | 客户端/目录 | 接收与归档 | 状态 | 操作
```

- 顶部保留“添加文件目录源”和“添加 RSyslog 接收源”。
- 新增和编辑复用同一个 `Modal`，标题明确显示操作和类型。
- 弹窗中按两列排列常规字段，路径字段占整行；移动端为单列。
- RSyslog 弹窗字段：设备 ID、日志名称、客户端 IP/网段、接收协议、监听端口、落盘目录、归档目录、归档保留天数、启用状态。
- 归档目录下明确显示“留空时原地压缩”。
- 弹窗的“保存并应用”会立即保存整个日志源列表并重载接收器，不再依赖页面顶部的全局保存按钮。
- 启停开关也立即保存；请求失败时回滚界面开关。
- 删除需二次确认，并说明删除配置不会删除已落盘或已归档文件。
- 操作列使用编辑和删除图标按钮，提供工具提示和可访问名称。
- 移动端不渲染宽表格，每个日志源使用紧凑摘要行，操作按钮保持可见。

列表中 RSyslog 的运行摘要显示“UDP/TCP + 端口”、配置客户端 IP，以及实际最后客户端 IP。还没有成功匹配消息时显示“尚未收到”，不使用虚构地址填充。

## API 和一致性

本次不新增独立 CRUD 路由，继续使用 `POST /api/settings` 保存完整 `log_sources` JSON，避免同时维护两套持久化协议。前端将列表增删改转换为一次原子列表更新。

`GET /api/receiver/status` 继续返回按 `source_id` 索引的状态，增加客户端和归档字段，不改变现有 JSON 顶层结构。未匹配客户端只写入限频服务日志，不伪造成某个日志源的接收计数。

## 并发与生命周期

- `ApplySources` 先构建和校验新路由快照，再在锁内替换当前端点集合。
- 共享端点的路由表在发布后不可变，接收协程不会读取正在修改的 slice/map。
- TCP 端点关闭时同时关闭监听器和已接受连接，避免旧路由在配置更新后继续写入。
- 归档调度器对每个 `source_id + date` 串行，不并发处理同一源文件。
- 接收写入错误和归档错误会更新状态，但不会因单个日志源失败停止其他端点。

## 测试策略

### Go 单元与集成测试

- UDP 和 TCP 都使用远端 IP 匹配正确的 `source_id/spool_dir`。
- 同端口多设备能共享监听器，精确 IP 和最长 CIDR 的优先级正确。
- 未匹配 IP 不写文件，拒绝计数增加。
- 重复匹配、非法 IP/CIDR、重复全匹配和非法归档路径在保存前被拒绝。
- 前一天 `.log` 产生可读 gzip，且文件名可被 `ExtractLogDate` 解析。
- 归档目录为空时原地压缩，非空时移动到指定目录。
- 重启补扫、已存在目标文件和跨文件系统移动保持幂等。
- 只删除超过保留期且入库状态为 `ready` 的归档。
- 日志源列表保存失败时，服务端设置和监听器保持原状态。

### 前端测试

- 列表不再同时渲染所有完整表单。
- 新增和编辑弹窗字段、默认值、校验和标题正确。
- 归档目录留空文案、默认 90 天和客户端 IP 必填校验存在。
- 编辑、启停和删除调用立即保存，失败时不会伪造成功状态。
- 1440px 桌面端和 390px 移动端无水平溢出，弹窗字段和操作按钮不重叠。

### 部署后验证

- 在同一测试端口配置两个客户端路由，验证 UDP/TCP 实际消息按 IP 落入正确目录。
- 人工创建前一天接收文件，验证压缩、可选移动、扫描可见性和入库完成后的保留期判定。
- 验证旧日志源配置能加载，且测试源在验证后被恢复/删除。

## 回滚边界

- 此改造只扩展设置 JSON，旧版本会忽略新字段。
- 回滚应用二进制不删除已压缩归档；归档文件名仍符合现有导入器协议。
- 编辑或删除日志源不删除 `spool_dir` 或 `archive_dir` 中的任何文件。
- 保留期清理是唯一允许删除归档文件的路径，且受 `ready` 状态保护。
