# 登录页业务流场景调整设计

## 目标

登录页背景只表达用户能理解的日志业务流程，不展示底层程序、数据库产品或实现组件名称。所有线路必须连接到节点边缘，不允许悬空、穿过节点或从节点另一侧无意义延伸。

## 节点文案

场景保留五个业务节点：

- 日志源：文件目录
- 日志接收：网络日志
- 数据存储：日志数据
- 日志查询：快速检索
- 压缩归档：按策略保留

删除 `RSyslog`、`ClickHouse`、`INGEST PIPELINE`、`SOURCE / RECEIVE / STORE / QUERY` 等技术或英文实现说明。协议名称不在背景场景中展示，真实协议配置仍保留在系统设置页面。

## 线路结构

主流程使用一条蓝色线路：

```text
日志源 -> 日志接收 -> 数据存储 -> 日志查询
```

归档使用一条绿色支线：

```text
日志接收 -> 压缩归档
```

线路规则：

- 每条线路从上游节点边缘出发，在下游节点边缘结束。
- 删除数据存储上方通往查询节点的重复灰线。
- 归档支线在压缩归档节点左侧结束，不穿过节点，也不向右继续延伸。
- 线路与节点之间保留清楚的层级关系，节点表面覆盖线路端点。

## 动画

- Anime.js 继续驱动线路粒子和节点图标呼吸效果。
- 蓝色粒子沿完整主流程循环移动。
- 绿色粒子沿归档支线循环移动。
- 删除已取消线路对应的查询粒子和动画实例。
- 页面隐藏时暂停循环；移动端和减少动态效果模式沿用现有降级策略。
- 动画仅使用透明度和 SVG 路径运动，不引入布局抖动。

## 动态 Logo

登录卡片使用自定义 SVG 盾牌校验 Logo，替换现有静态图标。Logo 只表达安全校验，不使用任何第三方程序、数据库或协议标识。

Logo 由三部分组成：

- 外层盾牌轮廓。
- 内层校验勾线。
- 一条限制在盾牌内部的低透明度扫光。

Anime.js 动画顺序：

1. 页面进入时绘制盾牌轮廓，持续约 420 毫秒。
2. 盾牌完成后绘制校验勾线，持续约 260 毫秒。
3. 空闲状态每 4 秒执行一次低透明度扫光，不缩放 Logo，不改变布局。
4. 登录成功时暂停空闲循环，校验勾线快速提亮一次，再执行页面离场动画。
5. 登录失败时 Logo 保持稳定，由现有登录卡片错误反馈承担提示，避免多个元素同时抖动。

Logo 动画由现有 `useLoginSceneMotion` 统一管理，并纳入作用域清理、页面隐藏暂停和减少动态效果降级。减少动态效果模式直接显示完整 Logo，不播放描边或扫光。

## 响应式与视觉

- 保持现有浅色网格、节点尺寸和登录卡片位置。
- 桌面端业务流不得进入登录卡片区域。
- 移动端继续隐藏背景业务流，只显示登录表单。
- 文案不得溢出节点，线路不得与文字重叠。
- Logo 固定为 34 像素方形区域，动画不得改变登录卡片标题行尺寸。

## 验证

- 更新登录动画静态测试，断言技术名称和英文遥测说明已删除。
- 断言只保留主流程与归档支线两条路径及对应粒子。
- 断言自定义 SVG Logo、Anime.js 描边动画和减少动态效果降级存在。
- 运行前端测试和生产构建。
- 使用本地 Chrome 分别检查桌面和移动视口截图。
- 桌面截图确认线路连接节点边缘、没有悬空线、没有进入登录卡片区域。
