# 登录页 Anime.js 数据流动效设计

## 背景

当前登录页采用左右双卡片布局，左侧 SVG 通过 CSS keyframes 展示日志流转，右侧提供管理员密码登录。现有页面功能完整，但场景与表单彼此割裂，动画节奏也分散在多个 CSS 规则中，不便于统一控制入场、登录成功、登录失败和响应式降级。

本次改造使用 Anime.js V4 重做登录页视觉与动效，不修改认证接口、Session 行为或登录后的控制台页面。

## 目标

- 将登录页改为全屏浅色运维场景，去除左右双卡片结构。
- 以数据拓扑和自动数据流作为第一视口的主要视觉信号。
- 使用 Anime.js 统一管理页面入场、循环数据流、登录成功和登录失败动画。
- 保持密码输入、键盘提交、错误提示和自动聚焦的可用性。
- 移动端关闭背景场景动画，只保留表单的轻量入场和提交反馈。
- 支持 `prefers-reduced-motion`，动效不可成为登录成功或失败处理的前置依赖。

## 非目标

- 不修改 `/api/login`、`/api/session`、Cookie 或密码校验逻辑。
- 不增加鼠标跟随、节点悬停改流向或其他持续指针交互。
- 不引入 Canvas、Three.js、WebGL 或额外粒子库。
- 不重构登录后的页面布局和全局主题。
- 不在场景中展示真实生产设备、地址、日志数量或运行状态。

## 视觉方向

### 整体布局

页面使用全屏浅灰白背景、细网格和低对比度 SVG 数据拓扑，不使用渐变光球或纯装饰性模糊色块。

- 产品标识和“NAT 日志控制台”集成到登录卡片头部，左侧不再放置独立品牌区。
- 数据拓扑铺满主要背景区域，但不遮挡登录控件。
- 登录表单固定在右侧，使用白色实底、细边框、8px 圆角和克制阴影。
- 登录区是唯一需要框定的工具区域，不再为左侧场景增加独立卡片。
- 拓扑使用设备、接收、存储和查询语义的简洁图形，不伪造线上数据。
- 卡片头只保留 Logo、产品名和“管理员登录”，删除“进入控制台”和产品功能说明，避免重复标题。

### 桌面端动效

页面首次显示时按以下顺序执行，整体入场控制在约 1 秒内：

1. 网格和产品标识淡入。
2. 四组拓扑节点依次出现。
3. SVG 链路从左向右绘制。
4. 三个数据粒子错峰进入循环。
5. 登录区最后进入并聚焦密码输入框。

数据流只自动运行，不响应鼠标。循环周期保持在约 5-6 秒，粒子使用错峰延迟，避免所有元素同步移动。

### 登录反馈

- 提交：按钮立即进入加载状态并阻止重复提交。
- 成功：暂停普通循环，数据粒子向终点汇聚，页面在约 350ms 内淡出，再调用 `onSuccess()`。
- 失败：登录区进行一次短促、低幅度的水平反馈，边框短暂切换为错误色，现有错误消息继续显示，密码输入框重新获得焦点。
- 动画不可阻断认证结果。Anime.js 未加载、动画 Scope 不可用或动效被禁用时，成功和失败逻辑直接完成。

### 移动端与减少动态效果

- `max-width: 900px` 时不创建背景场景循环，隐藏大部分拓扑节点和数据粒子。
- 移动端登录表单优先占据首屏，只执行一次淡入，不执行链路绘制和循环数据流。
- `prefers-reduced-motion: reduce` 时禁用循环、位移和路径绘制，所有内容直接显示。
- 页面在 `390x844` 下不得出现横向滚动、表单遮挡或按钮文字溢出。

## 技术设计

### 依赖

新增 `animejs@4.5.0`。该版本是设计时 Anime.js 官方最新版本，使用 V4 命名 ESM API：`animate`、`createScope`、`createTimeline` 和 `stagger`。

Anime.js 通过动态导入在登录页加载，登录后的控制台不保留动画执行实例。页面必须在动态导入失败时正常登录。

官方依据：

- GitHub: https://github.com/juliangarnier/anime
- React: https://animejs.com/documentation/getting-started/using-with-react/
- Scope: https://animejs.com/documentation/scope/
- Timeline: https://animejs.com/documentation/timeline/

### 组件边界

#### `LoginPage.tsx`

- 管理密码提交、加载、成功和失败状态。
- 持有登录页根节点引用。
- 调用动效控制器的 `playSuccess()` 和 `playError()`。
- 不直接拼装 Anime.js 时间线。

#### `LoginDataFlowScene.tsx`

- 只渲染确定性的 SVG 网格、路径、节点和粒子。
- 不读取认证状态，不发起网络请求。
- 使用稳定 class 名和 `data-*` 标记供作用域内动画选择。
- 场景作为装饰内容从辅助技术的阅读顺序中排除，不影响登录表单语义。

#### `useLoginSceneMotion.ts`

- 动态加载 Anime.js。
- 使用官方 `createScope({ root, mediaQueries })` 限定选择器和响应式条件。
- 创建一次入场时间线和桌面循环动画。
- 暴露 `playSuccess()`、`playError()` 和可用状态。
- 组件卸载时调用 `scope.revert()`，清理时间线、内联样式和事件状态。
- 避免在 React 重渲染时重复创建 Scope。

### 动画性能约束

- 优先动画 `transform`、`opacity`、SVG `stroke-dashoffset` 和路径进度。
- 不在循环中动画 `width`、`height`、`top`、`left`、`padding` 或字体大小。
- 不在动画帧内读取布局尺寸，不引入读写交错导致的强制布局。
- 场景 DOM 数量保持有界，不按视口尺寸动态生成大量节点。
- 动画实例必须遵循组件卸载、移动端媒体条件和页面隐藏后的暂停行为。

## 状态与数据流

```text
页面挂载
  -> 检查移动端和减少动态效果
  -> 动态加载 Anime.js
  -> 创建 Scope 与入场动画
  -> 桌面端启动数据流循环

提交密码
  -> loading=true
  -> POST /api/login
     -> 成功: playSuccess() -> onSuccess()
     -> 失败: playError() -> 显示错误 -> 输入框重新聚焦
  -> loading=false

页面卸载
  -> scope.revert()
```

## 异常处理

- 动态导入失败：记录开发期可诊断信息，生产登录流程直接降级为无场景动画。
- Scope 创建失败：页面内容保持最终可见状态，不隐藏表单。
- 登录失败：不重建整个场景，不重新播放页面入场。
- 登录成功动画异常：直接调用 `onSuccess()`，不得让用户停留在加载状态。
- 快速重复提交：沿用 `loading` 状态锁定提交按钮和表单提交路径。

## 测试与验收

### 自动测试

- 验证 `animejs` 依赖版本和 V4 命名 API 用法。
- 验证登录页包含全屏场景、登录工具区和独立 SVG 组件。
- 验证旧 CSS `login-flow-*` keyframes 被移除或不再绑定到登录场景。
- 验证 Scope 在卸载时执行 `revert()`。
- 验证成功、失败、动态导入失败和减少动态效果分支。
- 运行全部前端测试、TypeScript 检查和 Vite 生产构建。

### 浏览器验收

桌面 `1440x1000`：

- 场景非空，节点、链路和粒子均在正确区域。
- 登录区不与背景节点、标题或路径重叠。
- 入场后布局不跳动，不出现横向滚动。
- 登录失败只触发局部反馈，成功后按顺序退场。

移动端 `390x844`：

- 背景场景循环关闭。
- 登录表单完整显示在首屏，可使用键盘提交。
- 无横向滚动、文字裁切和按钮溢出。

无障碍与稳定性：

- `prefers-reduced-motion` 下内容直接可见且无循环动画。
- 密码输入自动聚焦；失败后恢复焦点。
- 浏览器控制台无未处理异常。
- 页面隐藏或组件卸载后不继续保留动画实例。
