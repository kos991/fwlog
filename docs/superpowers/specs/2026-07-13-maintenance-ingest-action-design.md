# 维护页入库操作交互设计

日期：2026-07-13  
范围：维护页「入库操作」卡片  
状态：待评审

## 背景

当前 V2 已支持按日志源触发手动入库和重建：前端会把选中的 `source_id` 带到 `/api/sync` 或 `/api/rebuild`，后端 `importHandler` 会根据 `source_id` 选择单个日志源；不传 `source_id` 时作用于全部启用日志源。

问题主要出在维护页表达方式：

- 「日志源」看起来只影响「手动入库」。
- 「重建日期」和「全量重建」被拆成两个区域，用户不容易判断二者关系。
- 「全量重建」虽然实际可以按日志源执行，但文案像是在重建所有日志源的所有历史日志。
- 单日重建和日期范围重建未来会共用同一类参数，当前 UI 只表达了单日。

## 设计目标

维护页入库操作统一改为「先选范围，再选操作」：

1. 先选择日志源。
2. 再选择日期范围：单日、日期范围，或不限制日期。
3. 再选择动作：手动入库或全量重建。
4. 最后通过一个主按钮执行，按钮文案直接说明真实影响范围。

目标是让用户在点击前就能看懂：

- 操作哪一个日志源，还是全部启用日志源。
- 操作哪一天、一段时间，还是所有历史日期。
- 是普通补入库，还是会覆盖重建。

## 术语

- 日志源：单个已启用日志源，或全部启用日志源。
- 日期范围：用户希望本次操作覆盖的日志日期范围。
- 手动入库：按增量逻辑补入库，不主动清理已完成日期的数据。
- 全量重建：按重建逻辑重新处理目标范围内的数据，属于高风险操作。
- 所有历史日期：不选择日期时，由后端扫描归档日志中存在的历史日期。

## 推荐方案：方案 3

使用一个统一的「入库操作」表单，按从上到下的顺序组织：

1. 日志源
   - 默认：全部启用日志源。
   - 可选：某一个已启用日志源。

2. 日期范围
   - 单日：选择一个日期。
   - 日期范围：选择开始日期和结束日期。
   - 所有历史日期：不限制日期，由系统扫描该日志源下已有历史日志。

3. 操作类型
   - 手动入库。
   - 全量重建。

4. 操作确认
   - 主按钮文案根据选择实时变化。
   - 全量重建必须弹出二次确认。
   - 二次确认文案必须同时包含日志源范围和日期范围。

## 页面交互

### 日志源选择

日志源控件保留当前数据来源：

- 第一个选项：全部启用日志源。
- 后续选项：已启用日志源列表。

显示文案建议：

- 全部启用日志源
- 深信服 NAT（示例，优先显示 `log_tag`）
- default（没有名称时显示 `source_id`）

日志源选择会影响全部动作，不再只放在手动入库旁边。

### 日期范围选择

日期范围使用一个明确的模式控件：

- 单日
- 日期范围
- 所有历史日期

不同模式下的参数：

- 单日：显示一个日期选择器。
- 日期范围：显示开始日期和结束日期。
- 所有历史日期：隐藏日期选择器，显示说明「系统会扫描所选日志源下已有历史日志」。

默认建议：

- 默认选择「所有历史日期」。
- 原因：当前手动入库的默认行为就是不传日期，由后端扫描可导入日期；这与现有逻辑兼容。

校验规则：

- 单日模式必须选择日期。
- 日期范围模式必须选择开始日期和结束日期。
- 开始日期不能晚于结束日期。
- 所有历史日期不需要日期参数。

### 操作类型

操作类型使用单选：

- 手动入库
- 全量重建

二者不是两个并列按钮，而是同一套范围参数下的两个动作。这样能直接表达：

- 「对这个日志源 + 这个日期范围，执行手动入库」
- 「对这个日志源 + 这个日期范围，执行全量重建」

### 主按钮文案

主按钮必须把影响范围说清楚。

示例：

| 日志源 | 日期范围 | 操作 | 按钮文案 |
| --- | --- | --- | --- |
| 全部启用日志源 | 所有历史日期 | 手动入库 | 入库全部日志源的所有历史日志 |
| 单个日志源 | 所有历史日期 | 手动入库 | 入库当前日志源的所有历史日志 |
| 全部启用日志源 | 单日 | 手动入库 | 入库全部日志源的所选日期 |
| 单个日志源 | 日期范围 | 手动入库 | 入库当前日志源的所选日期范围 |
| 全部启用日志源 | 所有历史日期 | 全量重建 | 全量重建全部日志源的所有历史日志 |
| 单个日志源 | 所有历史日期 | 全量重建 | 全量重建当前日志源的所有历史日志 |
| 全部启用日志源 | 单日 | 全量重建 | 全量重建全部日志源的所选日期 |
| 单个日志源 | 日期范围 | 全量重建 | 全量重建当前日志源的所选日期范围 |

按钮下方增加一行摘要：

> 本次操作：日志源 = 全部启用日志源；日期 = 所有历史日期；动作 = 手动入库。

### 全量重建确认

当操作类型为「全量重建」时，点击主按钮必须弹出确认框。

确认框文案必须包含：

- 操作类型：全量重建。
- 日志源范围：全部启用日志源或当前日志源名称。
- 日期范围：单日、日期范围或所有历史日期。
- 风险提示：会重新处理目标范围内的数据，耗时可能较长。

示例：

标题：

> 确认全量重建当前日志源？

说明：

> 本次将全量重建「深信服 NAT」的所有历史日志。该操作耗时可能较长，请确认当前没有其他入库任务正在执行。

确认按钮：

> 确认全量重建

手动入库不需要高风险确认，保留普通点击触发。

## 接口行为

### 当前可直接复用

当前后端已支持：

- `/api/sync`
  - 不传 `source_id`：全部启用日志源。
  - 传 `source_id`：单个日志源。

- `/api/rebuild`
  - 不传 `source_id`：全部启用日志源。
  - 传 `source_id`：单个日志源。
  - 传 `date=YYYY-MM-DD`：指定单日。
  - 不传 `date`：所有历史日期。

### 需要新增或补齐

日期范围模式需要支持开始日期和结束日期。建议接口扩展为：

```text
date_from=YYYY-MM-DD
date_to=YYYY-MM-DD
```

兼容规则：

- 只传 `date`：按单日处理，兼容旧调用。
- 传 `date_from` 和 `date_to`：按闭区间逐日处理。
- 不传日期参数：所有历史日期。
- `date` 与 `date_from/date_to` 不应同时传；若同时传，前端避免生成，后端可返回 400。

## 前端状态模型

建议替换当前 `fullRebuild` 开关式状态，改成明确的表单状态：

```ts
type IngestAction = 'sync' | 'rebuild';
type IngestDateMode = 'all' | 'single' | 'range';
```

核心状态：

- `importSourceID`: `''` 表示全部启用日志源。
- `ingestAction`: `sync` 或 `rebuild`。
- `dateMode`: `all`、`single` 或 `range`。
- `singleDate`: 单日日期。
- `dateRange`: 开始日期和结束日期。

这样比 `fullRebuild` 更清楚：全量重建不是一个附属开关，而是本次操作类型。

## 后端处理建议

后端保持现有导入入口，不新增独立业务入口：

- `importHandler(false)` 继续处理手动入库。
- `importHandler(true)` 继续处理全量重建。
- `selectImportSources` 继续负责 `source_id` 范围。
- `parseImportTargetDate` 可扩展为解析单日或日期范围。
- 执行层可以新增范围循环逻辑，复用当前单日导入能力。

如果本轮只先做 UI 清晰化，也可以先保留单日和所有历史日期，把日期范围控件隐藏到后续版本；但按用户当前要求，本设计把日期范围纳入本次实现。

## 文案规范

维护页文案继续使用项目当前中文风格，避免混用术语。

推荐统一用词：

- 日志源
- 全部启用日志源
- 当前日志源
- 日期范围
- 单日
- 所有历史日期
- 手动入库
- 全量重建
- 入库全部日志源的所有历史日志
- 全量重建当前日志源的所选日期范围

避免使用：

- 全量导入
- 重新导入
- 强制同步
- 重跑

## 验收标准

### 功能验收

- 用户可以先选择日志源，再选择日期范围，再选择操作类型。
- 用户可以对全部启用日志源执行手动入库。
- 用户可以对单个日志源执行手动入库。
- 用户可以对全部启用日志源执行全量重建。
- 用户可以对单个日志源执行全量重建。
- 单日模式会传递单日日期。
- 日期范围模式会传递开始日期和结束日期。
- 所有历史日期模式不传日期参数。
- 全量重建会弹出二次确认，且确认文案包含日志源和日期范围。
- 手动入库不弹高风险确认。

### 回归验收

- 已有 `/api/sync` 单源和全部日志源行为不退化。
- 已有 `/api/rebuild?date=YYYY-MM-DD` 行为不退化。
- 已有 `/api/rebuild` 所有历史日期行为不退化。
- 未启用或不存在的 `source_id` 仍返回错误。
- 维护页中文文案不出现乱码或中英混杂。

### 测试建议

- 前端测试：
  - 维护页不再使用 `fullRebuild` 开关作为交互核心。
  - 存在 `ingestAction` 和 `dateMode` 的清晰状态。
  - 主按钮文案能覆盖全部日志源、当前日志源、单日、日期范围、所有历史日期、手动入库、全量重建。
  - 全量重建确认文案包含日志源和日期范围。

- 后端测试：
  - `date` 单日兼容。
  - `date_from/date_to` 日期范围有效。
  - 日期范围开始晚于结束返回 400。
  - `source_id` 与日期范围组合能正确选择日志源。

- 构建验证：
  - `npm test`
  - `npm run build`
  - `go test ./internal/server`
