# 首次安装管理员初始化设计

## 背景

FWLOG 当前在完整安装包首次安装时生成随机密码并写入 `/etc/fwlog/admin-password`。运维人员需要登录服务器读取密码，首次使用流程割裂。账号安全页目前又采用居中限宽面板，与程序升级、威胁情报等系统设置页面的内容边界不一致。

本次改造将新安装流程调整为浏览器首次访问时设置管理员密码，不使用一次性初始化码；同时让账号安全页与其他系统设置页对齐。

## 目标与成功标准

- 新安装后首次访问直接显示管理员初始化页面，不显示普通登录页。
- 管理员账号固定为 `admin`，初始化页明确展示账号，只要求设置和确认密码。
- 初始化只能成功一次；成功后初始化接口永久关闭，并进入普通登录流程。
- 升级安装保留现有管理员密码，不出现初始化页面。
- 未初始化状态下，除初始化状态和初始化提交接口外，业务接口仍受保护。
- 账号安全内容区与程序升级、威胁情报页面使用相同左右边界，不再居中限制为 1120px。
- 桌面和窄屏均无横向溢出，密码表单本身仍保持合理宽度。

## 用户流程

### 新安装

1. 完整安装包不再创建随机 `/etc/fwlog/admin-password`。
2. 服务启动后没有环境密码、密码文件或已持久化密码哈希时，状态为“等待初始化”。
3. 浏览器查询初始化状态，发现未初始化后直接显示初始化页面。
4. 页面展示固定账号 `admin`，用户输入密码和确认密码。
5. 后端校验密码并以现有 PBKDF2-SHA256 格式保存哈希。
6. 保存成功后初始化状态立即关闭，前端切换到普通登录页，并提示使用新密码登录。

### 升级安装

- 已存在 `/etc/fwlog/admin-password` 的部署继续读取该文件，不删除、不覆盖。
- 已写入 ClickHouse `app_settings` 的管理员密码哈希继续生效。
- 升级包不创建初始化状态，也不重置任何凭据。

## 后端设计

新增两个无需会话但仅在未初始化时有效的接口：

```text
GET  /api/setup/status
POST /api/setup
```

状态接口返回：

```json
{"required": true, "username": "admin"}
```

提交接口接收：

```json
{"password": "用户设置的密码"}
```

密码沿用现有长度和复杂度校验。后端在同一进程内串行化初始化请求，并在持久化成功后才更新内存密码哈希。第二个及后续请求返回冲突错误，不能覆盖已创建密码。持久化失败必须显式返回错误，不能把初始化标记为成功。

本项目仍是单管理员模型，不引入多用户表、角色或账号管理；`admin` 只是固定登录身份的展示名称，普通登录继续使用现有密码/MFA方式，避免扩大认证契约。

## 前端设计

新增独立的首次初始化页面，沿用现有 FWLOG 蓝白配色、字号、圆角和品牌标识，不复制参考图的黑色主题。页面结构为：

- FWLOG 品牌标识和“初始化管理员”标题。
- 固定账号 `admin` 的只读信息行。
- 密码、确认密码和密码可见性切换。
- 明确的“创建管理员”主按钮。
- 创建成功后返回登录页，不直接伪造已登录状态。

应用启动时，初始化状态检查和会话检查并行执行；页面首屏立即渲染稳定外壳，不显示长时间空白。初始化状态优先级高于登录页，已初始化后不再加载初始化表单。

账号安全页移除 `.account-security-panel` 的 `max-width: 1120px` 和居中边界，使外层卡片与其他系统设置页完全对齐。内部密码/MFA双栏和密码输入最大宽度继续保留，避免表单被拉伸。

## 安全边界

由于用户明确不使用服务器初始化码，未初始化服务会接受网络中第一个成功的管理员创建请求。这是方案的固有风险，界面和安装说明应提示安装后立即完成初始化。

为降低实际风险：

- 初始化接口只在不存在任何有效管理员密码时开放。
- 初始化写入必须串行且只能成功一次。
- 接口限制请求体大小并复用密码长度校验。
- 初始化失败返回明确错误，不泄漏密码内容。
- 初始化成功后立即关闭入口，后续访问返回冲突状态。

## 打包与兼容

- DEB 和 RPM 完整安装脚本取消首次安装随机密码生成。
- 升级模式仍不得包含 ClickHouse 运行时，也不得改动现有密码文件。
- 离线安装包沿用系统包安装行为。
- 保留对 `ADMIN_PASSWORD`、`ADMIN_PASSWORD_FILE` 和已持久化哈希的兼容读取，便于已有部署继续升级。

## 验证

- Go：覆盖未初始化状态、初始化成功、重复初始化、并发初始化、持久化失败、已有密码兼容和受保护接口行为。
- Web：覆盖初始化页路由、密码确认、可见性切换、成功后进入登录页和账号安全全宽对齐。
- 打包：更新 DEB/RPM 脚本断言，确认新安装不生成随机密码，升级不覆盖现有凭据。
- 浏览器：检查 1920px、1024px 和移动端布局，无横向溢出。
- 测试机：只部署二进制验证已有账号兼容，不删除现有密码或模拟首次初始化；首次安装流程由隔离测试验证。

## 回滚边界

前端、初始化接口和打包脚本可随同一版本回滚。测试机已有 `/etc/fwlog/admin-password` 和持久化密码哈希均不迁移、不删除，因此回滚不会导致现有账号失效。
